## Изменения движка

- `relativeSpaces` и `absoluteSpaces` измеряют смещение в пробелах, от отступа опорной
  строки и от края соответственно. Значение 5 не превращается в 20 при indent.size=4;
  отрицательные смещения ограничиваются нулевой колонкой. Прежние стили измеряются
  шагами отступа. Новые значения импортируются, редактируются и сохраняются в IDE.
- Для таких профилей используются промежутки между токенами: SELECT-колонки, FROM/JOIN,
  WHERE/HAVING/GROUP/ORDER и хвосты SELECT обрабатываются также в хранимом коде; при
  subquery.useSelectFormatting=true общий стиль распространяется на вложенные запросы
  и CTE. Компактность коротких SELECT учитывается в модулях и подзапросах.
- Исправлены опорные позиции WHEN/ELSE/END, строк VALUES и длинных цепочек UNION.
  Ветки UNION привязаны к началу запроса, что устраняет последовательное исправление
  по одной ветке за проход. Legacy-профили проходят прежние golden-тесты.
- Совместная раскладка достигает стабильного состояния максимум за восемь проходов.
  TSF3006 сохраняет исходный SQL при цикле или превышении этого предела; TSF3007 — при
  изменении токенов сверх разрешённого профилем регистра. Это предупреждения с безопасным
  отказом. Сохранение исходного текста не считается подтверждением совпадения стиля.
- Общая проверка токенов учитывает только явно выбранные изменения регистра по AST.
  Литералы, комментарии, имена с preserve и последовательность/типы токенов проверяются
  точно; изменение `[nvarchar]` согласно профилю отличается от изменения `[ИмяОбъекта]`.

регистре экранированных встроенных типов и ручном выравнивании.

Повторите для Process и Right-aligned-EPM-AWB2. Историческое имя команды сохраняется;
режим all подходит любому нативному профилю. Без указания режима сохраняется прежний git
(история 2026 года); last-write выбирает дату на диске. Необязательный последний аргумент

защитные сохранения, ошибки исходного разбора и неподдержанная кодировка отдельно
регистрируются и не являются ошибкой выходного SQL.

При появлении установленного SQL Complete следует проверить числовые режимы на
небольших контрольных примерах с выводом в отдельные файлы. Его официальный
[CLI](https://docs.devart.com/sqlcomplete/using-the-command-line/automate-formatting-via-the-command-line.html)
поддерживает /sourcefile, /outputfile и /profile. Это позволит уточнить приближения,
не меняя исходные проекты и не принимая исторический SQL за однозначный эталон.
