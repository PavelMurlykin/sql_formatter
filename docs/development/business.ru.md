## 1. Продукт и ценностное предложение

T-SQL Formatter — бесплатное расширение для Visual Studio 2022/2026 и SSMS 20/22
с CLI для CI. Ядро ценности сегодня — единый корпоративный стиль SQL:
форматирование документа/выделения по настраиваемым профилям, импорт профилей
из SQL Prompt и SQL Complete, пакетная проверка и запись в CI.

Развитие направлено на то, чтобы после форматирования команда могла опираться
на те же механизмы для **контроля качества** (статический анализ), **скорости
написания** (сниппеты, генерация, преобразования) и **безопасности**
(восстановление работы, защита от опасных команд в продуктиве).

## 2. Целевые пользователи и сценарии

- **Разработчик БД** в SSMS/VS: ежедневное написание и ревью T-SQL, длинные
  скрипты миграций, типовые процедуры.
- **Ревьюер/лид команды**: единый стиль и автоматический контроль типовых ошибок
  до ревью и в CI.
- **DevOps/CI**: проверка форматирования и (после фазы 1) замечаний анализатора
  в пайплайнах без установки IDE.

## 3. Текущие возможности

- Форматирование документа, выделения; контекстное меню; отмена одной операцией.
- Настройки: именованные профили, группы правил, предпросмотр, RU/EN интерфейс.
- Импорт/экспорт профилей, в том числе конвертированные профили SQL Prompt
  (ADIR) и SQL Complete (AV, EPM, нативные альтернативы).
- CLI: stdin/файлы/каталоги, `--write`/`--check`, dotnet tool для CI.
- Четыре установочных пакета: VS 2022, VS 2026, SSMS 20, SSMS 22.

## 4. Конкурентное позиционирование

Сопоставление с SQL Prompt (Redgate) и SQL Complete (Devart) по итогам анализа
их официальных материалов (обсуждение с codex, октябрь 2026). Направления
отобраны по соотношению «ценность/сложность на текущей архитектуре».

| Направление | SQL Prompt | SQL Complete | Наш план |
|---|---|---|---|
| Статический анализ | да, +автоисправления | да | Фаза 1: правила, серьёзность, редактор и CI |
| Сниппеты | да | да | Фаза 2: встроенные + пользовательские JSON |
| Переименование переменных/алиасов | да | да | Фаза 2: batch/запрос-область, предпросмотр |
| Преобразования SQL | да | частично | Фаза 2: ограниченный набор с предпросмотром |
| Структура скрипта, навигация | да | да | Фаза 2: дерево скрипта, переход к объявлению |
| Автодополнение по схеме БД | да | да | Вне текущей дорожной карты (требует слой метаданных) |
| Генерация CRUD по таблице | частично | да | Фаза 3: из CREATE TABLE, без живого подключения |
| История/восстановление работы | да | да | Фаза 3: локальные снимки, поиск, восстановление |
| Цвета окружений, предупреждения | частично | да | Фаза 3: метки DEV/TEST/PROD, проверка опасных команд |
| Работа с результатами запросов | да | да | Фаза 3: TSV из буфера → IN/INSERT/статистика |

Сильная сторона проекта: открытость (репозиторий), локальность (без облака),
CLI для CI и конвертация уже существующих профилей команд, купивших
SQL Prompt/SQL Complete ранее.

## 5. Дорожная карта развития

Актуальные статусы — в [`ROADMAP.md`](ROADMAP.md). Кратко:

- **Фаза 1 — Статический анализ** (этапы 1–3): ядро правил → CLI `--analyze` →
  подсказки в редакторе.
- **Фаза 2 — Инструменты редактора** (этапы 4–7): сниппеты → переименование →
  структура скрипта → преобразования.
- **Фаза 3 — Метаданные и возможности SSMS** (этапы 8–11): генерация CRUD →
  история → окружения → работа с результатами.
- **Этап 12** — консолидированный выпуск и финальная документация.

## 6. Ценность новых возможностей по фазам

Раздел заполняется по завершении фаз: сценарии «до/после», измеримые эффекты
(время на ревью, доля замечаний, ловимых автоматически, восстановление потерянного
кода), история внедрения по этапам.

### Фаза 1 — Статический анализ *(этапы 1–2 из 3 выполнены)*

Готово ядро анализатора: пять правил первой очереди — `SELECT *`, `INSERT` без
списка колонок, `TOP` без `ORDER BY`, `UPDATE`/`DELETE` без `WHERE`. Для
`UPDATE`/`DELETE` без `WHERE` серьёзность по умолчанию — ошибка (риск массовой
потери данных), остальные — предупреждения; любую серьёзность можно изменить, а
отдельное правило — точечно отключить.

CLI-проверка `tsqlformat --analyze` работает для stdin, одиночных файлов и
каталогов, поэтому контроль качества SQL встраивается в CI без установки IDE:
код выхода 1 ломает сборку при замечаниях, формат вывода
`путь(строка,столбец): КОД [серьёзность] сообщение` удобен для разбора в
пайплайнах. Правила настраиваются в том же `.tsqlformatter.json`, что и
форматирование (секция `analysis`), — команда задает порог качества один раз
для редактора и CI.

Впереди: подсказки анализатора в редакторе VS/SSMS (этап 3). Оценка эффекта
(доля типовых замечаний, ловимых автоматически до ревью) — после этапа 3.

## 7. Ограничения и риски

- Автодополнение по живой схеме БД и отладчик T-SQL — вне текущей дорожной карты:
  требуют отдельной инфраструктуры (слой метаданных, серверные требования).
- Интеграции, зависящие от недокументированных API SSMS (окрашивание вкладок,
  перехват выполнения, прямой доступ к гриду результатов), выполняются по
  принципу best-effort с фиксацией фактического результата (ADR 0005).
- Все данные (история, снимки) — строго локальные; облачных компонентов нет.
