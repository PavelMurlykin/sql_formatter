## 1. Обзор системы

T-SQL Formatter — расширение для Visual Studio 2022/2026 и SSMS 20/22 плюс CLI,
форматирование T-SQL по настраиваемым профилям. Компоненты:

| Компонент | Целевая платформа | Ответственность |
|---|---|---|
| `TSqlFormatter.Core` | netstandard2.0 | Разбор (ScriptDom), модель layout-документа, рендеринг, правила форматирования; без IDE-зависимостей (ADR 0003) |
| `TSqlFormatter.Configuration` | netstandard2.0 | Форматирование опций, JSON-конфигурация `.tsqlformatter.json`, профили, обмен профилями SQL Prompt/SQL Complete |
| `TSqlFormatter.Cli` | .NET 10 | CLI: stdin/файл/каталог, `--write`/`--check`, локальный dotnet tool (ADR 0007) |
| `TSqlFormatter.IdeShared` | net4x/netstandard2.0 | Общая UI-логика настроек и окон для IDE-адаптеров |
| `TSqlFormatter.VisualStudio` + `VisualStudio2022`, `Ssms`, `Ssms20` | net472 VSSDK | Команды редактора, страница настроек, события сохранения; SSMS — best-effort (ADR 0005) |

Ключевые принципы: Core не знает об IDE; редакторские команды захватывают
снапшот текста, работают в фоне и применяют результат в UI-потоке одной
undo-транзакцией (ADR 0006).

## 2. Архитектура форматирования

Конвейер:

```
SQL-текст
  → ScriptDomSqlParser (Parsing/)        — AST, токены, тривиа (комментарии)
  → SqlParseResult                       — дерево + карта строк SqlLineMap
  → Builders (Formatting/Builders/)      — AST → Doc-модель (Layout/)
  → DocRenderer (Layout/)                — Doc → текст с учетом ширины строки
  → TextEdit[]                           — минимальные правки для редактора
```

- `ISqlParser`/`ScriptDomSqlParser` — разбор и диагностики разбора (`ParseDiagnostic`).
- `SqlSyntaxPolicy` — AST-based синтаксические политики (точки с запятой,
  необязательные квадратные скобки).
- `Formatting/*Options` + `RuleCatalog`/`RuleConfigurationV2` — настройки и профили.
- `EditorSqlFormatter` — фасад для IDE: принимает `FormatRequest`, возвращает
  `FormatResult` с правками; используется командами форматирования документов.

## 3. Сборка, тестирование и поставка

- Сборка: `dotnet build TSqlFormatter.sln`; тесты: `dotnet test TSqlFormatter.sln`
  (Core/Golden/ReleaseSmoke/SettingsUiSmoke).
- Релиз: `scripts/Build-Release.ps1` — четыре VSIX, CLI-пакет, профили,
  верификация (`Verify-Vsix.ps1`, `Verify-ReleaseProfiles.ps1`, `Verify-SettingsUi.ps1`).
- Результаты поставки и границы валидации — `release/VALIDATION.md`
  (installed-host валидация не подменяется успешной сборкой — AGENTS.md).

## 4. Функциональные модули

Разделы 4.x заполняются по мере завершения этапов дорожной карты.

### 4.1. Статический анализ SQL — этапы 1–3 *(запланировано)*

Ядро анализатора в `TSqlFormatter.Core/Analysis/`, CLI-режим `--analyze`,
интеграция в редактор. Детали будут добавлены по завершении этапов.

### 4.2. Инструменты редактора — этапы 4–7 *(запланировано)*

Сниппеты, переименование переменных/алиасов, структура скрипта, SQL-преобразования.
Детали будут добавлены по завершении этапов.

### 4.3. Генерация SQL по структуре таблицы — этап 8 *(запланировано)*

Разбор `CREATE TABLE` и генерация CRUD-заготовок. Детали будут добавлены.

### 4.4. История и окружения — этапы 9–10 *(запланировано)*

Локальные снимки редактора, восстановление закрытых скриптов, метки окружений,
проверка опасных команд. Детали будут добавлены.

### 4.5. Работа с результатами запросов — этап 11 *(запланировано)*

Преобразования TSV из буфера обмена: `IN (...)`, `INSERT`, статистика выделенного.
Детали будут добавлены.

## 5. Точки расширения

- Правила форматирования: `RuleCatalog` + билдеры `Formatting/Builders/`.
- Профили: `FormattingProfile`/`UserProfileStore`, импорт из JSON SQL Prompt/SQL Complete.
- CLI: `SqlFormatterCli` — единая точка входа, режимы форматирования.
- Новые правила анализа, сниппеты и преобразования — по контрактам модулей 4.x
  (описывается в соответствующих разделах по мере появления).
