# Установка T-SQL Formatter

Локальная сборка от 2026-10-31. Выберите пакет для своей IDE:

| IDE | Файл | Версия расширения |
| --- | --- | --- |
| Visual Studio 2022 17.14.x, x64 | `TSqlFormatter.VS2022.vsix` | 0.2.13 |
| Visual Studio 2026 18.x, x64 | `TSqlFormatter.VS2026.vsix` | 0.2.13 |
| SSMS 20.x, x86 | `TSqlFormatter.SSMS20.vsix` + `Install-SSMS20.ps1` | 0.6.12 |
| SSMS 22.x, x64 | `TSqlFormatter.SSMS22.vsix` | 0.6.12 |

Для готовых расширений .NET 10 SDK не нужен. Их целевая платформа — .NET Framework 4.7.2; зависимости форматирования включены в VSIX. VS 2022 старше 17.14 нужно обновить до ветки 17.14.

## Visual Studio 2022 и 2026

Закройте соответствующую Visual Studio, откройте её VSIX двойным щелчком, выберите нужный экземпляр IDE и завершите установку. Перезапустите IDE. Команды находятся в **Extensions → SQL Formatter**; откройте `.sql` и выберите **Форматировать документ**. SQL не выполняется. Правка отменяется одним Ctrl+Z; сохраните файл отдельно.

## SSMS 20

Закройте SSMS 20. Поместите VSIX и скрипт в одну папку. Откройте PowerShell **от имени администратора**, перейдите в эту папку и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-SSMS20.ps1
```

При нестандартном расположении SSMS укажите путь к папке, содержащей `Ssms.exe`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-SSMS20.ps1 -IdeDirectory "D:\Apps\SSMS20\Common7\IDE"
```

Скрипт проверяет поколение SSMS и содержимое пакета, устанавливает его в `Extensions\TSqlFormatter.Ssms20` и сохраняет предыдущую копию в `%LOCALAPPDATA%\TSqlFormatter\SSMS20\Backups`. Управляемые копии старого установщика внутри IDE переносятся туда же: SSMS мог находить их `.pkgdef` и загружать старую DLL. Неизвестные папки скрипт не перезаписывает и не перемещает. Для другого места копий укажите `-BackupDirectory`, обязательно вне каталога IDE. Используйте новый скрипт вместе с новым VSIX. Стандартный VSIX Installer для этой старой оболочки не подходит: VSIX служит контейнером для скрипта.

Запустите SSMS 20, откройте `.sql` без подключения к серверу и выберите **SQL Formatter → Форматировать документ**.

## SSMS 22

Закройте SSMS 22. Запустите VSIX Installer из установленного SSMS 22 и передайте ему `TSqlFormatter.SSMS22.vsix`. Пример для стандартного пути и текущей папки `release`:

```powershell
& "C:\Program Files\Microsoft SQL Server Management Studio 22\Release\Common7\IDE\VSIXInstaller.exe" (Join-Path $PWD 'TSqlFormatter.SSMS22.vsix')
```

Выберите экземпляр SSMS 22 в установщике и после установки перезапустите его. Найдите меню **SQL Formatter**; форматирование и анализ также доступны в контекстном меню SQL-редактора.

## Новые возможности и проверка после обновления

Пакеты включают завершённые этапы 1–9: анализ TSQL001–TSQL005, сниппеты,
переименование, структуру и навигацию, преобразования SQL, CRUD по CREATE TABLE
и локальную историю. Настройки анализа и истории находятся в **Настройки… → Общие**.

- Включите или отключите анализ, отдельные правила и их серьёзность. Анализ
  запускается командой **Проанализировать документ**. Явные поля `analysis`
  ближайшего `.tsqlformatter.json` перекрывают пользовательские значения IDE.
- История снимает SQL при сохранении и штатном закрытии, включая несохранённый
  документ и отброшенные правки. По умолчанию: включена, 100 снимков, 1000000
  символов, без срока хранения. Доступны лимиты 1–10000 снимков, 1–16777216
  символов и 0–36500 дней (0 — без срока).
- Нажмите **Сохранить** / **Сохранить и закрыть**. Закрытие без сохранения
  отбрасывает черновик настроек. Профили форматирования не меняют эти настройки.
  История независима от форматирования при сохранении; отключение сбора
  сохраняет уже записанные файлы в `%USERPROFILE%\.tsqlformatter\history`.

Для проверки используйте отдельный `.sql` в папке без проектной конфигурации.
Запустите анализ `SELECT * FROM dbo.ReleaseSmoke;` — ожидается TSQL001.
Сохраните файл с уникальным комментарием, добавьте ещё текст и закройте с отказом
от сохранения. Найдите оба состояния через **Восстановить закрытый скрипт**;
проверьте также закрытие нового несохранённого SQL. Восстановление открывает текст
в новом документе. SQL для проверки выполнять не нужно. Отдельные поля сервера/БД
могут отсутствовать; получение контекста живого подключения не проверялось.
Свежая установка именно этих версий в четыре IDE в этом выпуске не повторялась;
автоматические и предыдущие установленные проверки разделены в [отчёте](VALIDATION.md).

## Профили

В комплект включены нативные JSON v2:

- `ADIR_SQL_Main.json` — настройки, подготовленные по профилю SQL Prompt;
- `AV_Profile.json` и `Right-aligned-EPM-AWB2.json` — настройки по профилям SQL Complete, по 573 правила в каждом.

Откройте **SQL Formatter → Настройки… → Общие** (в Visual Studio сначала **Extensions**), нажмите **Импорт профиля…**, выберите файл, проверьте название и нажмите **Сохранить**. Повторите для каждого профиля. Активный профиль выбирается на любой из двух вкладок. Команда **Форматировать документ** форматирует выделение, а без выделения — весь активный `.sql`; она доступна и в контекстном меню. На вкладке **Общие** нажмите нужное сочетание в поле горячих клавиш и сохраните его. Язык и тема окна соответствуют IDE.

На вкладке **Форматирование** дерево состоит из четырёх жирных групп и 12 страниц с одним уровнем вложенности. Подробности редактируются справа; поиск ограничивает страницы и разделы параметров.

В этой сборке **ADIR_SQL_Main** удаляет необязательные квадратные скобки, добавляет
`;` после операторов и выравнивает цепочки `ELSE IF`. После обновления VSIX повторно
импортируйте `ADIR_SQL_Main.json`, замените сохранённую копию с тем же именем,
выберите её активной и нажмите **Сохранить**. Новые правила находятся в разделе
**Форматирование → Общие → Основные → Синтаксис SQL**; обязательные скобки сохраняются.

Ближайший `.tsqlformatter.json` имеет приоритет над выбранным профилем IDE. Для настроек проекта можно сохранить копию одного JSON под этим именем рядом с SQL-файлами, предварительно сохранив существующую конфигурацию. Исходные XML/style-файлы сторонних продуктов напрямую не импортируются. Конвертированные настройки имеют описанные в руководстве приближения и не обещают идентичный вывод SQL Prompt/SQL Complete.

[Результаты проверок](VALIDATION.md), [русское руководство](../docs/user-manual.ru.md), [English installation guide](README.en.md). `release-manifest.json` содержит SHA-256 установочных файлов и профилей; `profile-verification.json` — автоматическую проверку профилей. Дополнительный пакет CLI требует .NET 10 Runtime.
